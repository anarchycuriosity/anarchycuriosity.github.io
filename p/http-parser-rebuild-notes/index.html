为什么照着头文件抄容易卡住

我在rebuild我的tiny_web_server到http解析器的部分,我已经比较理解了设计意图,但是我不明白应该怎么样正确地抄这个部分,如果抄完头文件然后抄实现感觉跟抄字典没什么区别,头文件本身就没什么逻辑可言,而对于一些小的部分,我可以做到看一次实现然后想到思路然后默写下来,就像写算法题填空一样.我应该怎么做

从请求行一路推到请求体

按“一个输入把程序逼出一个新能力”的顺序 rebuild，而不是按文件顺序 rebuild。

也就是说，把 HTTP parser 当成一道越来越难的题,拿http parser来说,先问chatgpt然后让他帮你拆.这才是正解.

“parser记住当前阶段”
request_state state;

“记住扫描位置”
size_t scan_offset;

“头部大小写不敏感”
lower_ascii(...);

“不复制字符串，只看一个范围”
string_view;

“严格把十进制字符串变成整数”
from_chars;

“解析失败立刻进入终态”
result = parse_result::bad_request;
return result;

“request line结束，接下来按header规则解释”
state = request_state::headers;

你不是“不知道怎么系统思考”，而是还没有足够多的实现样本，让你的系统模型自动展开成代码步骤。

怎样安排第一次复刻

我在想抄的rebuild和只看解构而rebuild,它们之间的时间间隔也许应该大一些?毕竟抄一次其实也是在潜移默化地成长了?毕竟我抄一次之后我还要默写一次,我感觉我的兴趣和动力会减少.

我赞成，而且我觉得你这里抓到了一个很重要的点：“抄一次”和“只看解构重新 build 一次”不应该紧挨着做。

因为如果你今天刚完整抄完，明天就关掉源码重写，你测到的东西很大一部分其实是：

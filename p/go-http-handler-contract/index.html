Go net/http｜Handler、ResponseWriter 与进程内测试

2026-02-24
阅读时长: 3 分钟
... 次阅读

为什么先从硬编码开始？

需求：

  • GET /players/Pepper → 20
  • 以后还要支持其他玩家和记录胜场。

先不考虑存储。我们只验证一条链路：

1
2
3
4
5
6
7
8
9

客户端发出 GET 请求
        ↓
net/http 接收请求
        ↓
调用 PlayerServer
        ↓
PlayerServer 写入 "20"
        ↓
客户端收到 HTTP 响应

PlayerServer 暂时不知道 Pepper 是谁，也不知道分数来自哪里。

这不是完整实现，而是 TDD 的第一步：先证明一条最小路径能工作。

Handler 到底是什么？

Go 标准库要求 HTTP 请求处理器实现：

1
2
3

type Handler interface {
    ServeHTTP(ResponseWriter, *Request)
}

理解三个参与者：

对象 职责
http.Request 保存收到的请求，包括方法、URL、请求体
http.ResponseWriter 让 Handler 写入响应状态、响应头和正文
http.Handler 定义处理请求必须具有的行为

最初我们不需要创建结构体，可以直接写普通函数：

1
2
3

func PlayerServer(w http.ResponseWriter, r *http.Request) {
    fmt.Fprint(w, "20")
}

问题：普通函数没有 ServeHTTP 方法，为什么仍能交给服务器？

因为有一个适配器：

1

http.HandlerFunc(PlayerServer)

它把符合指定签名的函数转换成实现 http.Handler 的值。

注意：HandlerFunc 是一个函数类型，其 ServeHTTP 方法在内部调用被包装的函数，并不是凭空给原函数添加方法。

为什么测试不需要启动服务器？

使用：

1
2

request, err := http.NewRequest(http.MethodGet, "/players/Pepper", nil)
response := httptest.NewRecorder()

NewRequest 构造请求对象，NewRecorder 创建一个记录响应的对象。

我们直接调用：

1

PlayerServer(response, request)

执行路径变成：

1
2
3
4
5
6
7
8
9

测试代码
   ↓
构造 *http.Request
   ↓
调用 PlayerServer
   ↓
写入 ResponseRecorder
   ↓
检查 response.Body.String()

没有监听端口，没有真实 TCP 连接。

这能让测试快速检查 Handler 自身的行为，而不是网络环境。

一个容易忽略的错误

当前 GetPlayerScore 返回整数。

但 Go 的 map 有一个特点：

1
2
3
4
5

scores := map[string]int{
	"Pepper": 20,
}

fmt.Println(scores["Apollo"])

输出：

1

0

键不存在时，直接读取 map 会返回值类型的零值。

所以当前服务对不存在的 Apollo 返回：

1
2
3

HTTP/1.1 200 OK

0

问题并不只是正文不对。

200 OK 告诉客户端：请求成功。

但现在的业务要求是：玩家不存在，应返回 404 Not Found。

为什么只检查响应正文不够？

先加入一个新测试：

1

GET /players/Apollo → 404

预期旧实现失败：

1

got status 200, want 404

现在尝试一个明显错误的修复：

1
2

w.WriteHeader(http.StatusNotFound)
fmt.Fprint(w, score)

它让所有玩家都返回 404。

可是如果已有测试只检查正文：

1
2

Pepper → "20"
Floyd  → "10"

那么测试居然仍然可能全部通过！

这是原章最值得观察的一次反例。

测试通过只说明当前断言被满足，不代表整个响应正确。

因此已有玩家必须同时断言：

1
2
3

Pepper → 200，正文 "20"
Floyd  → 200，正文 "10"
Apollo → 404

WriteHeader 什么时候生效？

对 ResponseWriter：

1

w.WriteHeader(http.StatusNotFound)

会指定响应状态码。

如果没有显式调用 WriteHeader，第一次写入正文时默认发送 200。

例如：

1
2

fmt.Fprint(w, "20")
w.WriteHeader(http.StatusNotFound)

这样写太晚了。

因为第一次写正文时，200 已经被提交。

正确顺序是：

1
2
3
4
5

判断响应状态
       ↓
必要时调用 WriteHeader
       ↓
写响应正文

对于错误场景，本篇直接返回，不再继续写分数。

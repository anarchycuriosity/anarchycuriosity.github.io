共享文件与进程内缓存

假设两个进程同时运行。

T0：game.db.json = []

T1：HTTP 启动
    → 读取文件
    → HTTP Store 缓存 []

T2：CLI 启动
    → 读取文件
    → 记录 Ruth
    → 文件变成 [{"name":"Ruth","wins":1}]

T3：HTTP 收到 GET /league
    → 查询自己的内存缓存
    → 仍然返回 []

为什么？

因为 HTTP 进程没有重新加载文件。

当前实现中的 FileSystemPlayerStore 把 League 缓存在结构体里。另一个进程修改磁盘，不会自动修改这个结构体。

重新启动 HTTP 服务会重新读取文件，因此能够看到最新记录。

但仅仅增加“每次 GET 都重新读文件”也不足以获得安全的跨进程存储。

如果两个进程同时写入，各自按照旧快照重写整个 JSON 文件，就可能发生更新丢失。

初始：Ruth = 0

进程 B 读取 0

我们之前添加的 sync.Mutex 只保护同一个 Store 对象内部的并发访问，不能跨进程加锁。

真正需要多进程读写时，应考虑文件锁、事务、数据库或者单一写入服务。

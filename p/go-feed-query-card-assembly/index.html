2026-11-17

时间边界与查询数量

身份处理之后，Feed 调用：

db.MGetVideos(ctx, limit, &req.LatestTime)

本项目将 limit 定义为 30。

但它不是查询 30 位作者，也不是查询 30 条关注关系。

它查询的是最多 30 条视频记录。

5.1 查询条件

MGetVideos 的核心逻辑是：

  • 根据 created_at 限制时间范围；
  • 只选取创建时间早于 latestTime 的视频；
  • 按 created_at desc 倒序排列；
  • 最多取 30 条。

如果传入时间为 0，函数会在内部使用当前毫秒时间。

这是一个简单的按时间倒序排列的 Feed，并不是根据观看历史、兴趣或推荐算法计算出来的个性化信息流。

查询结果与返回对象

假设数据库只有以下两条满足查询条件的视频：

视频 ID 作者 ID 标题 CreatedAt UpdatedAt
101 7 海边日落 20:00:03.000 20:00:03.500
102 9 校园散步 20:00:02.000 20:00:02.500

另有两个作者：

用户 ID 用户名 头像对象名
7 Alice alice.jpg
9 Bob bob.jpg

假设查询时间边界为：

latest_time = 20:00:04.000

因此返回：

videos
  ├── db.Video{ID:101, AuthorID:7, ...}
  └── db.Video{ID:102, AuthorID:9, ...}

结果顺序是 101、102。

这里的 videos 类型是数据库模型列表：

[]*db.Video

但最终返回所使用的是：

[]*video.Video

二者代表不同层次。

db.Video 主要保存与视频表对应的字段，例如：

  • ID
  • AuthorID
  • Title
  • PlayUrl
  • CoverUrl
  • FavoriteCount
  • CommentCount
  • CreatedAt、UpdatedAt

而 video.Video 还需要完整作者对象、当前观看者点赞状态，以及可供客户端访问的媒体 URL。

另外，虽然 db.Video 模型中有 Author 关联字段，但当前 MGetVideos 没有通过 Preload 加载作者。

因此，不能认为查询出视频后，作者信息已经自动完整存在于 r.Author 中。

这就解释了为什么后面还需要循环。

从作者 ID 补齐作者信息

第一条视频：

r.ID = 101
r.AuthorID = 7

代码通过 GetUserByID(ctx, 7) 查询作者。

这里查询的是 users 表。

得到的数据库对象可以包含：

作者ID：7
用户名：Alice
头像对象名：alice.jpg
粉丝数、关注数、简介等

为什么不直接把 AuthorID=7 返回？

因为客户端需要显示 Alice 的名字、头像等资料，单独一个 ID 不足以构造完整作者信息。

但是也不应该把数据库用户对象直接不加选择地返回。

例如数据库模型包含密码字段，这不是视频卡片需要展示的内容。

因此，Feed 显式地从数据库用户模型中挑选所需字段，构造生成的 user.User 对象。

这里有一个很重要的区别：

user.User 是 RPC 数据类型，不表示调用了 User 微服务。

关注和点赞如何区分

现在已知：

观看者：42
作者：7

需要回答：

用户 42 是否关注作者 7？

源码调用：

db.GetRelationByUserIDs(ctx, 42, 7)

查询关系方向：

观看者 42
    │ 关注？
    ↓
作者 7

数据库中的关系可以表示为：

user_id to_user_id
42 7

如果存在匹配记录，返回非 nil 的关系对象。

最终：

IsFollow = relation != nil

如果不存在匹配记录，数据库函数将 ErrRecordNotFound 转成 (nil, nil)。

于是：

IsFollow = false

这里一定要区分：

  • 没有记录：正常业务状态，不代表数据库故障。
  • 查询失败：返回真正的错误，需要由业务处理。

现在需要回答：

用户 42 是否点赞了视频 101？

源码调用：

db.GetFavoriteVideoRelationByUserVideoID(ctx, 42, 101)

其关联对象不是作者，而是视频。

观看者 42
    │ 点赞？
    ↓
视频 101

假设存在：

user_id video_id
42 101

则：

IsFavorite = favorite != nil

为什么视频本身的 FavoriteCount 不能代替这个查询？

因为：

  • FavoriteCount=12：表示视频累计有多少点赞。
  • IsFavorite=true：表示当前观看者是否点过赞。

总数与个人状态是不同的业务问题。
